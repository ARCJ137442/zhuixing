# 结构组字产品定义与验证方案

> 产品代号：结构组字（暂名）  
> 定位：离线优先、以真实 IDS 文本为核心的极简汉字构形编辑器。  
> 本文合并产品探索和竞品分析两轮材料；需求、设计建议、用户故事与市场假设分别表述。产品承诺是待实现和验收的目标，不代表本次演示已具备全部能力。公开项目能力和许可应以对应版本及来源核查为准。

## 1 产品价值与范围

### 1.1 要解决的问题

古籍、族谱、地方志、姓名及特殊专业材料中，可能存在当前输入法或字体无法处理的字形。最初故事中的学者先查字典、再检索 Unicode、再试输入法，均未找到所需字，最终只能写“此处原字为某字形，暂以图片代替”。现实中应分别检查输入法找不到、字体缺字、地区字形不符和真正未编码，不能把这些原因合并判定。研究者常用图片代替，但图片难以按结构检索、复制后继续编辑，也容易丢失部件来源和构形过程。即使画出了字，后续修改、引用、交换和长期复现仍然困难。

结构组字的目标不是单次“输入后生成 SVG”，而是让一个构形经历完整生命周期：**书写结构 → 解析 → 呈现 → 展开 → 修改 → 撤销 → 导出 → 保存 → 未来恢复**。对象同时保留源表达式、结构关系和具体数据生成的视觉结果。

例如，研究者输入 `⿰木水`。这是演示性结构表达式，不保证对应规范汉字。数据充分时可获得预览、导出 SVG，并把原表达式交给同事；发现左侧部件有误时直接修改。若缺少绘制数据，则保留表达式、说明缺失，不能假装生成了正确字形。

| 能力 | 普通文本工作流中的常见情况 | 产品目标 |
| --- | --- | --- |
| 输入已编码字符 | 支持 | 保持普通文本输入 |
| 表达未编码字形结构 | 说明文字、图片或专用工具 | 直接书写 IDS |
| 将结构转为视觉结果 | 通常需外部工具 | 对支持的数据生成字形 |
| 修改构成 | 重做图片或寻找原设计文件 | 展开源表达式，局部修改 |
| 保存构形来源 | 往往不完整 | 保存来源、依赖、版本和修订 |

### 1.2 正式产品定义

产品计划采用离线优先 PWA，以一个主要输入区域承载自然文本与 IDC 输入。解析器将源文本转为结构模型，数据适配层解析部件依赖，渲染器根据可用字形数据生成 SVG。可逆编辑不是从 SVG 猜测结构，而是恢复一直保留的原始 IDS。

第一阶段不替代完整字体编辑器、不建设公共 Wiki 或云端协作平台，不承诺任意 IDS 都可生成规范汉字，也不承诺每份表达式对应唯一字符。首要目标是证明：文本驱动的构形及可逆编辑，能够降低真实任务成本。

### 1.3 术语与责任边界

| 概念 | 含义及边界 |
| --- | --- |
| IDC | 描述部件相对结构的真实 Unicode 字符；快捷键仅为输入方式 |
| IDS | 用 IDC 与描述成分形成的结构序列；并非完整字义、字源或唯一字形定义 |
| 未编码字符 | 没有对应标准 Unicode 编码的字符；不能仅由显示失败判定 |
| 缺字 | 当前字体或软件无法正确显示所需字符；可能已有编码 |
| 异体字形 | 同一字符在地区、规范或文献场景中的不同形式 |
| KAGE 数据及引擎 | 具体笔画、几何及部件引用数据与绘制机制；不是 IDS 本身 |
| SVG | 一次渲染的视觉输出；不天然包含可恢复的完整构形语义 |
| 项目文件 | 保存构形、来源、版本、修订与必要依赖的可编辑资产 |
| 私用区 PUA | 依赖使用者约定解释的码位；不保证跨系统语义一致，也不应作为对象唯一身份 |

IDS 描述构件关系，不规定唯一绘制结果；相似结构不等于文字学上的同一个字。系统支持 IDC 不意味着规范要求它必须重建字形。相关 Unicode 规范版本与原文引用见第 12 节。2026-10-20 核查发现 Unicode 18 的章节可读，但版本页存在状态矛盾；不据此断言发布日期或完整实现最新标准。

## 2 不可混淆的产品原则

### 2.1 真实文本优先

逐字输入、快捷键插入、复制粘贴，最终都产生相同的 IDC 字符序列。IDC 可选择、复制、粘贴、退格删除、中间修改、撤销和重做。

不采用“快捷键创建隐藏左右节点，再把部件塞入节点”的独立命令系统。快捷键只产生普通字符插入事务，不改变表达式语义。相同有效 IDS，在同一解析器、渲染器、数据版本和配置下，应产生相同结构和构形结果。

原提案的 `Ctrl+方向键` 只保留为待测试候选，不写死默认映射：它可能与按词移动光标、系统或输入法操作冲突。组合输入期间不触发构形快捷键；移动端基本操作不能依赖物理键盘。

### 2.2 源文本与结构模型各有权威范围

**源文本是构形表达的权威输入；构形树是解析后的权威结构模型。** 二者不能悄悄覆盖彼此，也不能把节点 ID、缓存或隐藏状态当作源文本的替代品。

`⿰⿱宀女木` 的外层是左右结构，左侧为 `⿱宀女`，右侧为 `木`：

```text
⿰
├── ⿱
│   ├── 宀
│   └── 女
└── 木
```

纯文本重新解析也能实现局部修改，不应声称“没有树就做不到”。结构模型的价值是清楚关联源范围、SVG、局部重绘、历史、光标和缓存。节点按需保存稳定 ID、类型、操作符、子节点、源文本范围、语法状态、渲染状态和版本/缓存标识。

### 2.3 完整 可渲染 合格是不同状态

`⿰氵青` 可以语法完整，却缺少 KAGE 定义、递归依赖或适合目标地区的部件。不能只用一个“成功”覆盖全部阶段。

| 独立维度 | 状态示例 | 需要回答的问题 |
| --- | --- | --- |
| 语法 | 未完成、完整、非法 | 操作符和操作数关系是否成立 |
| 数据 | 齐全、缺失、版本异常、引用异常 | 绘制所需依赖是否可用 |
| 渲染 | 未渲染、成功、失败 | 是否实际生成视觉结果 |
| 质量审查 | 未审查、待确认、已审查、已知问题 | 是否符合目标风格、规范和用途 |

结构成功不等于渲染成功，渲染成功不等于规范合格；近似结果应标明近似之处。结构完整但数据缺失时，应显示例如“结构完整，但缺少一个部件的绘制数据”，并继续保存源文本。

## 3 编辑与呈现体验

### 3.1 一个主输入区 必要时解释

默认打开即可输入，不设强制欢迎页、教程、模式切换或常驻候选栏。普通文字保持普通文本，不完整 IDS 保持可读。避免把部件选择、结构按钮、树面板、属性、候选与导出工具全部铺开，让用户为了写一个字操作复杂软件。

极简不等于无反馈。用户需要知道为何未生成、缺什么、如何展开和导出。桌面悬停或光标定位时可显示原始 IDS、部件、数据状态及操作入口；触屏使用点击或等效操作。解释按需出现，而不是要求用户理解内部引擎。

能力分三层：

1. 核心：输入、解析、呈现、局部修改、展开、撤销、SVG 导出。
2. 必要解释和恢复：原 IDS、部件、数据来源/状态、展开入口。
3. 后续高级流程：项目文件、数据修订、批量构形、多字形比较、字体生产、协作与长期版本。不全部放进常驻主界面。

### 3.2 完整与提交分离

用户输入 `⿰`，状态为缺两个操作数；输入 `⿰人`，仍缺一个；输入 `⿰人木`，结构完整。未完成时可以用极细虚线、淡化提示或轻微占位说明等待，但不生成错误的残缺字形。

“完整”由语法决定；“提交为字形呈现”由交互策略决定。用户可能马上改部件，因此不应一完整就强制替换为难编辑的 SVG。可等待短暂停顿、允许明确提交、保留文本、随时展开，并在继续输入时根据光标及结构重判。

原材料提出约 **300 毫秒**提交延迟，作为实验起点而非最终标准；需测试输入速度、表达式长度和不同 IME。

### 3.3 动画服务理解而非游戏化指标

建议从 **150–200 毫秒**局部转换试验：字符与部件向中心靠拢，文字淡出，SVG 从略小尺寸显现，光标仍在合理位置。可用于说明结构完成、内层完成、缺操作数或局部修改影响。

动画必须短促、局部、可打断。连续输入更安静，不整页抖动、不强制完整播放，不增加音效、分数、连击、排行榜或奖励系统。动画不是数据更新的前提；被打断后直接进入稳定状态，不能遗留半透明节点或把新字符插错位置。

### 3.4 输入法 光标 撤销先于动画

不能只监听 `keydown`。需结合 `beforeinput`、`input`、`compositionstart`、`compositionupdate`、`compositionend`、选区和组合状态。规范只是基础，不能替代真实浏览器、系统和中文输入法测试。

主要风险：拼音候选未确认时，方向键被误当作 IDC 快捷键；中间编辑时渲染更新 DOM，把光标移到末尾。输入正确性优先于视觉效果。

建议验证顺序：普通文本 → 中间移动光标 → 正确插入/删除 → IME → 粘贴/替换 → SVG 后逻辑选区恢复 → 撤销/重做 → 动画。

撤销围绕用户理解的编辑事务，而非 DOM 或渲染步骤。已呈现字形应能恢复可编辑表达式，但自动视觉合并不一定单独占用一条撤销记录；输入、结构修改、展开与呈现的历史粒度仍需明确测试。不能完全依赖复杂 `contenteditable` 的浏览器默认历史。

## 4 解析 架构与数据治理

### 4.1 增量输入模型

解析器必须处理嵌套、中间编辑、删除操作符、不完整粘贴和结构更换，而不是只解析已完成字符串。

| 输入 | 预期解释 |
| --- | --- |
| `⿰` | 缺两个操作数 |
| `⿰木` | 缺一个操作数，可继续输入 |
| `⿰木水` | 左右结构完整 |
| `⿰⿱宀女木` | 嵌套结构完整 |
| 修改内层 `⿱` 为 `⿰` | 更新受影响结构，保留外层与其他文字 |

IDC 不只有左右、上下二元结构，也包括包围、三元和规范版本相关的一元形式。实现应明确采用的 IDS 语法与 IDC 集合，逐个定义元数，不把所有操作符当成等待两个操作数。只支持一部分时，应声明子集，而不是声称完整规范支持。

推荐数据流：文本事务 → 确定变更范围 → 更新解析树 → 失效受影响缓存 → 解析部件依赖 → 局部渲染 → 恢复逻辑光标。稳定节点 ID、版本与缓存用于减少重算，不限制用户直接编辑文本。

### 4.2 IDS KAGE SVG 分层

IDS 表达关系，KAGE 数据及绘制策略决定具体几何，SVG 记录结果。同一 IDS 可因数据、部件定义和风格不同产生不同字形。保持适配层与渲染接口稳定，有利于替换引擎和支持多风格，而不要求用户重新学习语法。

SVG 中的 `data-ids` 等元数据只是附加信息；外部软件可能移除它，不能据此承诺任意 SVG 可恢复结构。

### 4.3 三层数据治理

| 层 | 职责 |
| --- | --- |
| 原始来源 | 原记录、版本、来源标识和引用关系；不混入无记录人工修改 |
| 目标字形 | 按大陆或其他目标体系筛选、替换、修订，记录每次修改 |
| 构形映射 | IDS 操作数到具体定义的映射；处理别名、缺失、引用链和版本差异 |

解析器不负责来源选择，渲染器不负责规范审查。不能把 GlyphWiki 全部数据直接当作已审查大陆字形全集。不同体系的部件即使能画出，也可能比例、连接、穿插或风格不协调。

正式支持的部件/结果应记录：来源、数据版本、目标字形体系、依赖关系、人工修订、审查状态、已知问题。不要没有定义测试集、标准和统计方法就宣称“准确率 97%”。

可从 **30 个有意挑选的高风险样本**开始，而非只测容易成功的常用字：复杂笔画、位置变体、递归引用、跨源差异、缺失/版本异常、容易混淆日本与大陆字形的样本。目标是找出自动处理、人工修订及暂不支持的边界，不是做漂亮成功率。

### 4.4 许可证独立核对

分别建立代码、IDS 结构数据、部件数据、字体和导出产物的许可清单。开源不等于任何组合与重新分发均被允许。

2026-10-20 核查确认 `@kurgm/kage-engine` 仓库明确 GPL v3；采用时仍须核对具体版本及分发义务，不能因浏览器可运行就认定适用所有发布模式。CJKVI-IDS 不同文件可能有不同许可；GlyphWiki 数据、引用内容、KAGE 引擎与最终字体也需分别审核。核查结果以第 12 节及配套核查记录为准。

### 4.5 保留精修出口而不提前复制字体软件

纯 IDS 无法表达所有轮廓和笔画细节。例如 `⿰女木` 的左部倾角不符合目标文献时，用户可能要改一条笔画。模型可预留部件定义、局部位置调整、轮廓修订和数据版本，但第一版不必实现完整画布、控制点或大量几何参数。

## 5 离线 保存与交换

### 5.1 离线能力等级

| 等级 | 定义 | 产品判断 |
| --- | --- | --- |
| L1 | 已缓存界面、脚本等，页面可离线打开，部分数据缺失 | 早期原型目标，不能代表完整离线 |
| L2 | 初始化后，解析器、渲染器、支持的字形及全部依赖本地可用；离线编辑、生成、导出 | 第一版合理正式目标 |
| L3 | 项目独立保存、重开、跨设备导入，保留原 IDS 和版本及必要复现信息 | 本地优先的进一步目标 |

只缓存 HTML/JS 不够。断网验收必须实际完成编辑、修改、生成、导出和恢复支持范围内的项目。联网更新数据不能悄悄改变旧项目含义。

### 5.2 三种输出不要混为一谈

1. **SVG**：用于显示、嵌入、文档、排版和视觉讨论；应有明确几何边界和兼容性。它不是标准 Unicode 语义字符，不天然参与全部文本搜索或输入，各软件支持也不同。
2. **结构化项目**：继续编辑与长期复现。建议保存原 IDS、项目结构/稳定节点 ID、部件引用、来源和数据版本、应用及渲染器版本、可选几何修订、必要 SVG 快照、生成环境和格式版本。
3. **字体或 PUA 输出**：后续专业需求，需要字体生成、码位分配和互操作设计，不是 SVG 导出的免费附属能力。

仅保存远程部件名称不足以保证几年后能重现；需定义依赖打包或可恢复的版本化引用策略，并遵守数据许可。项目对象保留稳定身份，不以 PUA 码位作为全球唯一标识。

应用版本、渲染器版本、字形数据版本、项目格式版本应分别记录。恢复时优先复现原结果，缺旧数据时说明原因；改用新数据必须提示可能变化。第一版用本地项目文件验证价值，不需要云账号与复杂项目平台。

## 6 六个核心用户故事

> 以下均为设计叙事，用于检验假设，不是已经完成的访谈或已证实的需求。

### 6.1 林先生首次上手

林先生是构形爱好者，不懂字体设计，曾因部件面板与选项繁多放弃工具。他打开一个输入区，输入 `⿰木水`，停顿后看到字形；悬停查看 IDS，展开后把 `木` 改为 `人`，再次观察。验证首次成功时间、能否独立开始、是否理解仍可编辑，以及是否区分缺数据与未完成。

### 6.2 陈女士局部纠错

陈女士为教学材料输入 `⿱宀女`，发现上方部件不对。她展开并替换 `宀`，其他文字与外层结构不变。验收目标是生成后的修改不比第一次输入复杂得多；展开依赖保存的源记录，而非图像识别。

### 6.3 赵先生多路径输入

赵先生粘贴同事发送的嵌套 IDS，次日使用快捷键输入同一表达式。他期待解析、结构关系和视觉输出相同。固定引擎、数据与配置，比较逐字、快捷键和粘贴路径；不一致即缺陷，不能要求用户改变习惯。

### 6.4 王先生遇到数据缺失

王先生输入未编码古文字形的完整 IDS，却无法预览。系统明确“结构完整，但缺少部件”，他可保留记录、稍后补数据或换已有定义。有近似输出时标注限制。验证用户能否定位问题，而不是反复删字猜测语法错误。

### 6.5 李女士断网工作

李女士在家完成初始化后到图书馆整理材料。网络中断，她仍能编辑已支持构形、重开本地项目并导出 SVG。网络恢复可检查数据更新，但不能自动改旧项目。此故事验证的是完整任务，不只是页面启动。

### 6.6 三年后的接收者

研究者保存 SVG、IDS 和版本，三年后交给另一人。接收者能了解原始表达式、所用数据、是否可复现及升级可能变化，并继续编辑。验证可交换构形记录的价值，但不据此提前建设协作平台。

## 7 用户与市场假设

### 7.1 六类相关市场

| 类别 | 用户任务 | 典型项目/替代方案 | 产品关系 |
| --- | --- | --- | --- |
| 构形查询 | 一个字由什么组成 | CJKVI-IDS、HanziCraft | 知识和入口参考 |
| IDS 检索 | 哪些字有某种结构 | YAIST、IDS 数据库 | 上游工具及相邻工作流 |
| 字形绘制编辑 | 调部件、笔画和轮廓 | KAGE Editor、GlyphWiki | 直接技术及任务竞品 |
| 字体设计 | 管理大量字形并生产字体 | FontForge、FontLab、FontCreator | 专业替代与下游 |
| 学习研究 | 理解、记忆和分析汉字 | HanziCraft、研究工具 | 潜在用户来源 |
| 未编码/特殊字形处理 | 表达、显示、保存、分享 | 自定义字体、PUA、图片/SVG | 核心机会假设 |

公开工具生态存在，不等于证明独立付费市场存在；此分析不是对所有商业、封闭或中文互联网产品的穷尽审计。差异化应靠完成任务的成本验证，不能声称市场上无人覆盖类似环节。

### 7.2 七类潜在用户

| 用户 | 主要可能价值 | 必须验证的限制 |
| --- | --- | --- |
| 汉字文化爱好者 | 拆字、组合、即时反馈 | 新鲜感之后是否持续创作 |
| 古文字与文献研究者 | 准确结构、来源、追溯、长期编辑、文档可用 | 需求频率、准确性与付费意愿 |
| 语言学和汉字研究人员 | 部件分布、结构记录、批量导入/搜索/导出 | 数据互通可能比动画重要 |
| 教育工作者 | 部件关系和 IDS 互动实验 | 结构不是字源，练习符号不是规范字 |
| 字体与文字设计师 | 初始构形、减少重复操作、导入精修 | 是否真节省时间、轮廓质量与来源 |
| 非遗 地方文献 特殊字符整理人员 | 姓名、地方用字和专业材料的稳定记录传递 | SVG 无法独自解决文献规范与字体兼容 |
| 独立创作者 | 小说、游戏、世界观和符号系统创作 | 不一定追求大陆规范，更重速度和自由 |

第一轮材料的目标人群概括为爱好者、研究教学、字体工作者；第二轮进一步细分为七类。建议验证优先级：①未编码字形创作者及特殊字符整理者；②研究者与文献工作者；③爱好者与教育工作者。这是任务验证顺序，不是市场规模排名或已选定付费客群。

### 7.3 任务替代比功能名称更重要

用户可能只想让地方志中的字正常打印并被别人查看。若换一个覆盖更广的字体、输入法或字符检索就能解决，不应要求他学习构形工具。只有需自行构造且未来还要改的任务，才更可能体现产品价值。

输入法、字符搜索、扩展字体、PUA 字库、插入图片和专业绘图都是任务替代。必须验证“字形如何进入真实文档，并在他人环境中继续可用”，而非只展示编辑器内效果。

## 9 机会 路线与非目标

### 9.1 七项后续机会

1. **构形草稿纸/实验室**：快速比较 `⿰木水` 与 `⿱木水`，降低试验成本。“十秒钟试验”是故事，不保证十秒生成规范字；比较多候选可先用历史快照/项目副本，而非立即增加候选栏。
2. **可分享的构形对象**：同事拿到 IDS、SVG、来源、版本、限制与依赖，能继续编辑，而不只是看图片。三小时制作的特殊字形，三个月后仍有修改价值。
3. **教学实验**：学生输入 `⿰日月` 再改上下结构，学习关系、语法和构形/字形区别；可研究教学练习文件，不开发首版课程、积分或学习管理系统。
4. **可追溯实验记录**：记录初始表达式、部件替换、导致最终结果的变更和参与数据；轻量撤销与长期版本是不同需求，可共用事务基础但不等于立即造版本控制平台。
5. **结构化符号创作**：小说/游戏作者组合汉字式部件、左右和包围结构，导出到地图、道具、界面。自定义符号不自动成为标准汉字或获得编码。
6. **一组字的共享关系**：研究共同部件、局部结构、影响范围、缺数据和多版本；先建立模型，等批量真实需求出现再考虑图谱界面。
7. **数据质量维护工具**：定位缺失引用、待审规范、旧部件和版本差异；普通用户看简洁状态，维护者用独立审核工具，不把后台全部放入主界面。

### 9.2 首版闭环与实施次序

首版先验证一个字形的生命周期：输入 IDS → 解析 → 可用数据生成 SVG → 修改部件 → 撤销 → 展开再编辑 → 导出 SVG → 保存项目 → 离线重新打开。

路线建议：

1. 证明真实文本驱动比现有工作流更直接。
2. 证明生成后仍可稳定修改和恢复。
3. 建立来源清楚、质量受控的部件数据。
4. 再依据真实需求进入研究、教学、特殊字符处理及字体生产。

暂不追求覆盖所有汉字或自建完整数据库。拥有一万个可生成字形，不代表编辑和恢复可靠。

### 9.3 原方案决策表

| 原想法 | 结论 | 落地约束 |
| --- | --- | --- |
| 单输入框 | 保留 | 默认主界面，必要反馈不省略 |
| IDC 真实文本 | 保留 | 不可被隐藏命令取代 |
| 快捷键输入 | 修正后保留 | 仅插入字符，避开 IME/光标冲突 |
| 完整后自动 SVG | 修正后保留 | 完整与视觉提交分离 |
| 俄罗斯方块式动画 | 克制保留 | 理解优先，可打断，不抢编辑控制 |
| 未完成保留文本 | 保留 | 轻量提示，不画错误残缺字形 |
| 构形树 | 精确定义后保留 | 源输入与结构模型各自负责 |
| 仅靠操作符栈 | 不作核心架构 | 明确解析完整/未完成/非法输入 |
| 直接打包 GlyphWiki | 修正 | 来源、许可、版本、依赖和规范审查 |
| 只有 SVG 输出 | 扩展 | 本地可恢复项目也重要 |
| 最后处理 IME/光标 | 否决 | 早于动画验证 |
| 完整结构立即强制合并 | 否决 | 交互策略不等于语法规则 |
| 同一套隐藏状态驱动全部 | 否决 | 文本事务与显式模型分层 |
| PWA 能打开即离线 | 否决 | 按真实离线任务验收 |

### 9.4 明确不承诺

- 任意 IDS 都生成符合大陆规范的字形，或每份结构对应唯一汉字。
- 任意外部 SVG 自动恢复原始 IDS，或所有软件保留 SVG 元数据。
- 首版支持所有罕见部件、完整字体生产或复杂云协作。
- 不同数据版本始终得到相同视觉结果。
- 自动生成即经过规范审查；IDS 即字源、字义或权威识别结果。
- 为动画牺牲输入、光标、恢复与错误解释。

## 10 研究 验收与风险

### 10.1 三类访谈

| 对象 | 具体问题 | 判断用途 |
| --- | --- | --- |
| 最近一年遇过缺字的人 | 最近何时、当时任务、如何解决、耗时、是否交付、长期保存要求、字体不兼容或无法再编辑经历 | 查真实频率和替代成本，不问空泛“喜不喜欢” |
| 研究者和文献整理者 | 如何记录罕见字、保不保留结构、是否比较方案、论文/数据库用途、最耗时及最不满意环节 | 区分质量规范与记录/快速导出的优先级 |
| 字体设计师和文字创作者 | 是否接受文本构形、哪些可自动组合、哪些必手调、轮廓能否作草稿、SVG/项目能否接工作流 | 判断专业补充价值而非新颖程度 |

### 10.2 三种产品实验

| 实验 | 设计 | 观察 |
| --- | --- | --- |
| A 文本驱动 | 输入 IDS，即时解析和渲染 | 理解表达式/字形关系，能否修改，需要何种提示 |
| B 增加自动合并反馈 | A 加短动画与未完成提示 | 是否帮助理解、等待过长、妨碍连续输入、对 IDS 新手有无帮助 |
| C 优先可逆编辑 | A 加展开、局部修改和撤销 | 纠错速度、生成后编辑、嵌套理解 |

实验用于区分用户真正重视自动生成、动画还是可逆性。若可逆性更重要，不为动画延后编辑；若动画确实改善理解且无干扰，再保留。

### 10.3 观察任务与六项指标

至少观察 **五位不熟悉项目的人**，不急于指导，让他们完成左右结构输入、改部件、撤销、展开、SVG 导出和断网重开项目。反复找不存在按钮意味着反馈缺失；不懂为何失败意味着状态解释不足；怕改坏意味着可逆性没传达；把快捷键当特殊命令意味着文本模型表达失败。

| 指标 | 测量方式 |
| --- | --- |
| 首次成功时间 | 从打开到首个受支持表达式的可用预览或成功导出，预先统一成功定义，不以页面加载计 |
| 修改成本 | 改一部件的步骤、耗时、错误；是否重输、丢光标、破坏外层 |
| 结构可逆性与恢复 | 展开、修改、重合并、撤销重做、保存重开 |
| 失败可解释性 | 用户能否自行区分未完成、非法、缺部件、引用异常、渲染失败 |
| 离线完整性 | 初始化后断网完成构形、修改、保存、重开、导出 |
| 数据可信度 | 来源、版本、依赖、修订和审查是否可读、可解释 |

这些指标应与任务替代方案对照，而非只数功能。支持更多 IDC 但修改要重输，不一定胜过支持较少结构而编辑稳定的产品。

### 10.4 需求验收清单

- [ ] 真实 IDC 可直接输入、选择、删除、复制、粘贴和中间编辑。
- [ ] 同一最终 IDS 的逐字、快捷键、粘贴路径语义及固定条件输出一致。
- [ ] 操作符元数和支持语法明确；不完整/非法/完整分别识别。
- [ ] 缺数据、版本/引用异常、渲染失败、未审查不混为成功。
- [ ] 原 IDS 始终保存，呈现后可展开，无需从图像猜测。
- [ ] 局部修改尽量保持外层、其他文字和逻辑选区。
- [ ] IME 组合不被快捷键/动画破坏；连续输入不丢字、不跳光标。
- [ ] 撤销重做语义清楚，视觉转换不会制造不可理解的历史。
- [ ] 动画短促局部可打断；断后稳定，无半透明残留。
- [ ] SVG 边界正确、导出可用，项目保存与 SVG 明确分开。
- [ ] 项目记录版本及依赖，能恢复；无法复现时说明原因。
- [ ] 断网实测支持范围内全闭环，而非仅启动页面。
- [ ] 桌面与触屏可完成基本任务，必要解释有可达入口。
- [ ] 目标字形质量与许可按来源、版本分别审核。

### 10.5 五类失败风险

| 风险 | 应对 |
| --- | --- |
| 有趣但无持续需求 | 测真实工作、频率和重复使用，不只看演示反应 |
| 结构正确但字形差 | 分离解析、渲染和质量；高风险样本、目标体系审查 |

## 11 商业方向与长期价值

以下都是待访谈和实际使用验证的假设，不能推导可靠市场规模、付费转化率或收入预测。

| 方向 | 可能价值 | 风险与前提 |

### 12.4 2026-10-20 核查增补

本轮技术核查详见配套 `research.md`，范围是解析、编辑边界和部分许可，并未重做全部竞品或市场调查。

- Unicode 17 与本次可读的 Unicode 18 第 18 章，对以下 **17 个 IDC** 元数一致。Demo 固定使用此表，不宣传实现全部最新版字符属性。
- 一元：`⿾`（水平镜像）、`⿿`（旋转）。三元：`⿲`、`⿳`。二元：`⿰ ⿱ ⿴ ⿵ ⿶ ⿷ ⿸ ⿹ ⿺ ⿻ ⿼ ⿽ ㇯`。
- `⿼` 是右包围，`⿽` 是右下包围；`㇯` 以原部件及待移除部件为两个操作数，语法完整不代表可做出有意义的减法。不以覆盖白块或重叠冒充减笔。
- 严格 IDS 叶节点范围需按规范处理表意字符、部首、CJK 笔画 U+31C0–U+31E5、私用字符、全角问号；不把 ASCII、emoji 和普通标点悄悄当严格部件。`〾` 是序列外近似指示符，不是另一种一元 IDC。支持自由创作扩展时需明确声明。
- 五个操作符 `⿼ ⿽ ⿾ ⿿ ㇯` 的引入可参见 [UTC 173 决议 173-C18/C19](https://www.unicode.org/L2/L2022/22241.htm)。另见 [Unicode 17 第 18 章](https://unicode.org/versions/Unicode17.0.0/core-spec/chapter-18/)、[Unicode latest](https://www.unicode.org/versions/latest/) 和 [Unicode 18 版本页](https://www.unicode.org/versions/Unicode18.0.0/)。
- 混排的 `⿰木木木` 应是一个完整 IDS 加普通 `木`。空格/换行可作为明确边界；不得删除不支持字符后伪造成功。源范围应与 textarea 的 UTF-16 偏移一致，词法按码点遍历；深度/长度上限是应用限制，不是 Unicode 规定。
- CJKVI-IDS 官方 README：`ids.txt` 来自 CHISE，遵其条款；`ids-ext-cde.txt` 非直接来自 CHISE，不受同一 GPLv2 限定，**不等于公有领域**；其他数据标 GPLv2。数据含 CDP 实体及地区后缀，不能整列当纯 Unicode IDS。
- GlyphWiki 当前官方许可页读取失败，**许可未完成核实**：[待核入口](https://glyphwiki.org/wiki/GlyphWiki:データ・記事のライセンス)。不能断言全部数据 CC0；本次 Demo 不内嵌该数据。

## 13 对外简述

结构组字让你直接写出一个字的构成。输入 IDC 和部件，系统理解它们之间的关系，在数据允许时生成字形。你可以展开、修改、重新生成、导出 SVG，并保存为未来还能继续编辑的构形记录。

它的目标不是让用户更快得到一张汉字图片，而是让汉字结构成为可以直接书写、理解、反复修改、重新生成和长期保存的对象。是否能形成独立市场，仍需真实用户任务、竞品对照和持续使用数据证明。

### 14.3 设计与开发依据

本项目采用极简默认界面、按需披露、输入路径等价和真实状态原则；保持领域模型与 DOM 适配边界、单一变化源、异步归属与故障处理。

源模型、DOM偏移转换、浏览器事件与CompositionMotion分别组织。动画仅得到展示权限，不写source、selection或history；其几何与Core布局共用来源。旧17条部件路径逐字节保留，新增字体轮廓由构建脚本从固定SHA256字库提取。接管评估是Agent代码审阅，不代表维护者已经完成审美审批或真实接管。

### 14.4 动效、来源与实际验证

- 稳定结果不依赖动画结束才成立。继续输入、选中、展开、撤销、新一轮转换、滚动、resize、页面隐藏或离开会取消旧展示，旧异步回调不能清除新会话。系统减少动态效果、缺少WAAPI或批量超过18个叶部件时直接显示稳定结果。
- 源码仍是真实文本而非透明输入层。12个传统IDC内嵌最小WOFF子集；本机字体不含五个新IDC，不能保证它们在所有设备中显示。未知部件但布局已支持时采用明确字体回退；不支持布局仍保留原文并说明原因。
- 字体来源为 [Noto CJK官方仓库](https://github.com/notofonts/noto-cjk)，版本、范围、SHA256见源码包的components-provenance.json，OFL全文随单HTML和源码包保留。新增宋体与旧简笔笔风不同，这是兼容旧绘制契约的代价；组合不等于规范汉字。不以形似猜测Unicode映射。
- 48项核心、22项行内模型/DOM夹具、16项兼容/几何/动画生命周期、5项受控宿主、20项可注入时钟的自适应节奏、18项已有字/删除、6项实际keydown handler受控夹具、20项选区命令、19项完整输入流程受控宿主及15项字体回退检查通过。已用本机Inkscape实际栅格化并检查4个引擎SVG，轮廓可见、布局未裁切；这不是应用运行截图或动画验收。
- 真实浏览器、IME、触屏、跨浏览器选区/剪贴板、下载和断网重开仍未验收。
- 动效没有完成外部视频参考的逐帧对照验收。


### 14.5 自适应交互（0.1.3）

语义先行：源编辑、历史、光标和选区仍立即更新。自适应只改变“何时呈现字形”和“用多久展示归位”，不把动画完成当提交条件；新输入立即取消旧动画，不排队、不补播。

- 直接单码点键入与删除按成功且确实改变source的事件采样。相邻间隔指数平滑，至少两个有效间隔才推断快输入；停顿按真实时间连续衰减，不把重新开始的第一个字突变为慢速模式。
- compositionupdate及组合中的input不采样。一次有效compositionend最多记录一次确认，不把确认文本长度伪装成多次按键。短间隔连续确认只提供加速证据；长候选词选择时间不是慢打字样本。一次确认达到4个码点时作为批量，直接呈现稳定结果。
- 粘贴、示例插入、导入和撤销不贡献打字速度证据，断开键入/确认采样链；既有速度倾向只随时间自然衰减。格式操作、未变化的source和过期IME回调不计入。
- 手动利落/自然/慢看是基础偏好，而非阻碍快编辑的最低时长。关闭动效、减少动态效果、隐藏/离页状态优先；自适应不能将它们重新开启。

初始策略值（工程参数，尚未实机校准）：正常等待300ms、最短80ms；自然动效620ms，按手动档缩放后最多压缩82%，非静态时最低80ms。95ms以内间隔视为快端、450ms为慢端，至少3个间隔且均值达到65ms以内可静态；350ms恢复宽限后以700ms时间常数平滑恢复，1600ms以上间隔不连接为同一键入链。间隔平滑权重0.35，加速0.65、直接键入慢向放松0.2；IME只取加速方向。

InputPacing是可注入时钟的纯展示策略，不持有source/selection/history写权限；CompositionMotion通过duration注入消费结果，inline-app仍拥有语义事务。确定性单元测试验证阈值、取消资格、停顿恢复和IME分类，不证明某设备的帧率、输入延迟或“丝滑”。真实验证应观察帧间隔/掉帧及输入反馈延迟分布，不能用单一平均FPS代替体验证据。

### 14.7 0.1.5 选区命令、用户叙事与源保护

### 14.8 0.1.5 动效可见性诊断与修复

确定性根因：0.1.4动效preferences.enabled本来就是true，且不读写持久化设置；但capture明确排除了Unicode匹配，因此默认命中仁/明等时从未启动动画，不能归咎于用户关闭。其他抑制包括系统减少动态效果、页面隐藏/pagehide、无WAAPI、极速duration=0、批量预算和源DOM位置不可测。本轮没有真实浏览器画面证据，不能推断实际设备究竟命中了哪一条。

- Unicode显示也进入真实输入→settle→capture→play链：源叶部件的文字从测得位置归入最终字槽并淡出，真实Unicode结果始终已存在；轮廓短确认表达“形成结果”。这不是把自绘几何笔画变成规范字体笔画。SVG路径归位保持原流程；继续输入/选择/撤销仍立即取消。

- 更多菜单提供按需“查看动效状态”，说明关闭、系统偏好、无可新收起结构、预算降级、坐标降级或正常模式；不把诊断常驻首屏。native DIV/P/BR输入树的位置映射通过DOM适配器反查源偏移，避免只遍历顶层子节点而抓错位置。

### 14.9 0.1.6 功能优先的字体回退

“尔”的路径缺失属于需要明确降级的资产覆盖问题。模型根因是0.1.5的atom资格只允许已核Unicode匹配或纯路径ready；完整且支持布局但缺路径时，也被阻止合成呈现。现在将“结构能排布”和“资产具有纯轮廓”分离：动画能力不再成为功能前提。

- Core.status继续如实返回missing资产状态，新增previewKind区分outline/font/source；Core.layoutLeaves成为纯轮廓、字体回退和动效共用的布局几何来源。格式、rendererVersion、dataVersion及旧项目兼容规则不变，不把系统字体存成伪造路径依赖。
- 已核⿰亻尔仍显示你，不依赖尔路径；未核但完整可排布的⿰木尔等进入字体回退atom。它是原IDS的可逆显示，不推断Unicode身份。缺件时采用全叶字形的静态SVG text预览，用本机Noto Serif CJK SC/serif字体，等比放入部件槽位；不是纯轮廓，也不是规范字形。某设备可能仍没有罕见字字体，外观/缺字取决于字体覆盖，不能保证跨设备一致。
- 未完成、非法字符、未支持IDC布局和带不明附着修饰符的结构仍保留原文，不用回退假造解析或布局。点选、选区展开、复制IDS、保存、退格、撤销及合字命令不依赖动画；已核Unicode转换继续使用同一小表。
- 正常反馈让源叶文字归入其真实布局槽，再以虚线轮廓确认字体回退；下方简短文字同时说明“字体回退/缺轮廓/依赖本机字体”，不只靠颜色传达，也不每次弹toast。稳定字体预览在动效期间不隐藏。极速或位置测量降级沿用短非空间确认；手动关闭、reduced-motion、隐藏、无WAAPI或API抛错时保持同一个可编辑稳定结果，不把偏好解释为失败。
- 纯轮廓SVG导出继续受missing资产限制。另设“导出字体依赖SVG”，包含静态text、精确IDS元数据、portableOutlines=false标记及字体依赖说明，无脚本、事件属性、外链或外部字体资源。旁边说明换设备可能不同；文件名带font-dependent，不冒充纯轮廓。用户源字符和元数据统一XML转义，包括<、>、&和引号。
- 本轮15项字体回退模型/转义/导出契约检查，以及完整inline-app宿主新增6项（总19项）覆盖未知结构与已核你两条路径、关闭匹配、off/reduced/hidden/API抛错、未支持布局、选中复制/编辑undo和实际导出handler的Blob内容。总计189项。另用标准XML解析器读过两个实际输出及转义压力样例；这只证明静态XML有效，不是字体视觉、浏览器Range、真实输入法或动效丝滑验收。
- 0.1.5原件已备份；0.1.6不混入独立光学校正研究，也不提前塞入下一轮视图/操作单位/设置系统。用户叙事和候选矩阵依然是设计材料，不自动升级为全量通过。
