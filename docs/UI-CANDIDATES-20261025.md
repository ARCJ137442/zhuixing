# 缀形工作台 UI 候选 · 2026-10-25

状态：本地 UI 候选，未发布；其中品牌标志已获用户审美批准并升格为正式产品标志，其余界面仍按候选状态记录。

## 设计任务

缀形的首要操作是把真实 IDS 原文写下来、移动其中的选区，再观察可逆的结构呈现。首屏必须同时表达“可编辑原文”和“当前呈现/身份状态”；许可、数据和构件边界要能找到，但不能与每次编辑争夺注意力。源文本、Unicode 身份、构形布局和字形数据能力是不同事实。

## 候选方向

| 方向 | 首屏构图与阅读路径 | 信息如何展开 | 代价与依据 |
|---|---|---|---|
| A · 丝线构形工作台（已实现） | 左侧 IDS 编辑画布为主，右侧只读构形观察与身份/呈现状态；窄屏改成上下阅读 | IDC/示例和操作由编辑器按钮打开；结构/来源细节保留原详情入口，许可摘要落在页面底部 | 主编辑对象和结果并列，连续输入无需滚走查看状态。右侧只是编辑区的只读呈现，不另造第二份业务状态。 |
| B · 标本研究桌（未实现） | 顶部对象身份带 + 中央字形标本 + 底部结构谱系横带，整页更像可比对的研究对象 | 每个字符先成为标本，再按部件/来源/字频沿下方轨迹展开 | 更适合已经选定字符、做横向比较的场景；当前源工程没有字词/拼音检索和多来源关系数据，照此构图会伪造主入口或留出空的研究面板。 |
| C · 书写长页（未实现） | 单列、近似宽页纸张；IDS 编辑在首位，呈现结果紧随其后，其他信息顺序向下 | 结构信息和来源按顺序成为页内章节，尽量不并列侧栏 | 编辑空间直观、窄屏迁移自然；桌面需在输入与结果之间垂直扫动，编辑时不易同时对照结果和状态。 |

选择 A，是因为现有能力以编辑 IDS 为中心，且能让源码、结果、身份和预览状态同时可见。这个选择没有把 HanziCraft / Hanping 的检索与词典面板塞入不具备相应数据的当前版本。参考资料原始清单和边界见本任务调研交接记录。

## 视觉与状态决定

- **正式品牌图形：** 采用用户通过的原图轮廓，由“缀”的纟偏旁与“形”的彡部件组合；左棕右绿，保留原有笔形，不增添新笔画或装饰。权威 SVG 为 app/branding/zhuixing-logo.svg；单文件应用内嵌相同路径，品牌名称仍以“缀形”短字标配“汉字构形工作台”副题呈现。小尺寸清晰度见随候选维护的 24/30/34/64px 检查图。
- **颜色语义：** 墨色承载正文，鼠尾草色标示工作区/焦点，赭红强调当前动作。普通构件中性；不按外形猜测声符、义符、部首或字源。身份/呈现状态以文字和符号补充，不只靠色彩。
- **主次：** 空白保留在输入与观察区域周围；用间距和细分隔线表达关系。输入、状态、结果各有稳定区域，详情仍由用户主动打开。许可摘要在底部，完整第三方许可随详情展开；软件许可待维护者决定仍明确说明。
- **响应：** 820px 以下调整工作区比例，640px 以下把观察区移到编辑器下方，窄至 380px 时缩小 IDC 网格列数。2026-10-25 在本地 HTTP 页面 390×844 CSS px 视口检查了侧栏开合、4列 IDC 网格和4列部件网格；`documentElement.scrollWidth` 为375px，没有横向溢出。窄桌面观察区展开时浏览器报告664×1012 CSS px，网格列宽352px/254px，页面宽仍为664px。
- **原文边界：** 右侧预览只复制现有渲染结果，不参与编辑、历史或保存；身份未核、缺字、未支持布局和字体回退沿用已有引擎状态，不因皮肤改造猜测补齐。

## IDC 快捷输入矩阵

默认不占据编辑画面：编辑器获焦时按住 `Alt`，17 项 SVG 候选才贴近光标出现；直接按候选上的方向/字母键插入，松开 `Alt`、按 Escape、失焦或切为只读立即收起。Shift+方向键始终照常扩选，不再有需要记住开关状态的 Shift 模式。快捷输入可以在设置中关闭；关闭后，17 个 SVG 按钮仍然可用。

四种分置沿用直觉方向：`Alt+←` → `⿰`、`Alt+→` → `⿲`、`Alt+↑` → `⿱`、`Alt+↓` → `⿳`。包围用方向/角落提示，变换类用短助记键；显示层同时给出 SVG、中文名和键帽，初次使用无需先背表：

| 快捷键 | IDC | 记忆线索 |
|---|---|---|
| `Alt+← / → / ↑ / ↓` | `⿰ / ⿲ / ⿱ / ⿳` | 分置轴向与方向；反向分成三列/三层 |
| `Alt+O / T / B / L / R` | `⿴ / ⿵ / ⿶ / ⿷ / ⿼` | overall、top、bottom、left、right |
| `Alt+Q / E / Z / C` | `⿸ / ⿹ / ⿺ / ⿽` | 左上、右上、左下、右下的近似键位 |
| `Alt+P / M / G / −` | `⿻ / ⿾ / ⿿ / ㇯` | pile/叠加、mirror、转动、减号 |

字母快捷键按物理键位置 `KeyboardEvent.code` 分派；如果浏览器提供 `Keyboard.getLayoutMap()`，HUD 和完整提示会把键帽改为当前布局实际字符，否则回退到标准键位名。W3C 将 `key` 定义为受当前布局影响的键值、将 `code` 定义为不随布局改写的物理位置；MDN 明确指出 `code` 本身不适合直接当作所有键盘布局的用户标签，并给出 Keyboard Layout Map 作为显示依据。[W3C UI Events](https://www.w3.org/TR/uievents/) [MDN KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code) [MDN Keyboard API](https://developer.mozilla.org/en-US/docs/Web/API/Keyboard_API)

这些按键仍是候选而非真人验收结论：微软官方 Edge 快捷键表把 `Alt+←/→` 用作后退/前进，因此这四个分置快捷键不能宣称跨浏览器无冲突；它们保留在本地候选里，是因为方向与结构意义直接对应，是否值得承担宿主冲突由真人设备试用决定。[Microsoft Edge keyboard shortcuts](https://support.microsoft.com/en-us/edge/keyboard-shortcuts-in-microsoft-edge) 字母组合也受系统、输入法及键盘布局影响。组合输入、229、AltGraph、重复、额外修饰、只读和非编辑器焦点由代码过滤。任何键位冲突都可从设置关闭，插入面板是可见且无需快捷键的后备路径。受控宿主验证只能证明代码分派，不证明宿主一定把该事件交给网页。

工作台遵循“常驻最少、注意范围内展开”：观察侧栏默认折叠，用户需要对照结果时手动展开；插入结构、偏旁搜索、快捷提示和许可详情均按需打开。移动设备依赖可点选按钮，不要求修饰键。偏旁面板有61项，32个偏旁写法、29个常用字根，能按字符/名称筛选并把真实 Unicode 叶字符插入当前光标。

17 个符号均可写入源文本；最后5个当前无几何布局，按钮和候选图均明确标注。菜单、编辑区、观察预览和快捷提示共用内嵌 SVG；source 仍是 Unicode IDC 字符，未来未配置的符号保留 Unicode 回退呈现。

## Shift 偏旁输入试验：从 O 符到单项快捷键

第一项精确映射采用用户提出的 `Shift+F → 扌`。它只在可编辑区、编辑器聚焦且 IME 没有组合时生效；插入沿用普通 Unicode 源文本事务，一次撤销即可恢复。设置默认启用但可以关闭。纯 `Shift+F` 与本机 Rime 现有的 `Ctrl+Shift+F` 简繁切换不同；程序要求不带 Ctrl/Alt/Meta，所以不会接管那条组合。Shift+方向继续扩选。

码表调查结果不能解释为“每个字母有一个唯一部件”。用户提供的 `flypy.txt` 是带有私人使用说明的小鹤音形定制码表；本次只读，没有修改或把整表复制进产品。其 `#5 符号`区包含26个 `ob*` 字母组、94条候选；`obf` 本身有5个候选，其中 `扌` 与其他部件/标记共享编码。`ofpp` 是41项部件选择，当前61项偏旁面板覆盖24项、尚有17项未收录；`ofjg` 12项是IDC，`ofjt` 14项是方向/箭头符号。小鹤官方更新日志还把“符号组之外的 o 符”作为可有重码的候选组管理，因此 `Shift+F → 扌` 是本产品主动选出的精确快捷键，不是 `obf` 的无歧义直译。[小鹤音形官方更新日志](https://flypy.cc/win_record.html)

本机 Rime 的 `default.custom.yaml` 把单独左 Shift 设为 `noop`，`Ctrl+Shift+F` 切换简繁，`Shift+Alt` 切换 ASCII；纯 `Shift+F` 与该全局 Ctrl 组合不同。不过当前 Flypy schema 的 `speller/alphabet` 同时含大小写字母，并带 `uppercase` 翻译标签，所以输入法组合期间的大写 F 仍可能有实际含义；本应用在 IME composition/229 时明确不拦截。Rime 官方资料允许 Shift 单键具有输入模式语义；默认配置中左右 Shift 的处理也可不同。因此应用只在空闲编辑器中匹配纯 Shift+F，并要求在实际 Weasel/键盘上试验左、右 Shift；不同 Rime 前端和输入方案仍需实机验证。[Rime 自定义指南](https://github.com/rime/home/wiki/CustomizationGuide) [Rime 默认配置](https://github.com/rime/rime-prelude/blob/master/default.yaml) [Rime ASCII composer](https://github.com/rime/librime/blob/master/src/rime/gear/ascii_composer.cc)

Luna 的用户视角复核也支持“只给明确的一对一快捷键，重码保留候选选择”：初次作者能继续点61项图形/文字按钮，熟练作者可用 `Shift+F` 快速插入 `扌`；例如编辑 `⿰亻…` 时按一次 `Shift+F` 插入提手旁，若打错可立即撤销。面对 `obf` 等一键多候选，不应静默替用户挑选；应继续用可搜索面板，未来只有在人工挑选、命名和 IME 测试后，才扩展其它 Shift+字母。

本地浏览器试验验证了 `Shift+F` 插入 `扌`，随后 Ctrl+Z 恢复原文；`Ctrl+Shift+F`、IME 组合、只读、重复与关闭设置由受控测试验证为不消费。浏览器合成事件不能证明真实 Rime 的 Shift 组合行为，所以该映射目前是桌面候选，不是所有输入法/手机都已验收的承诺。

用户原图给出的上包围图样作为包围类母型：24 单位 SVG 画布内，外虚线方框占 `2..22`，内括形占 `6..18`，平行边距均为 4。上/下/左/右包围复用同一 `12×12` 三边括形；四角包围使用相同 12 单位边长、以相邻方向镜像/旋转；全包围内框也居中。左右/上下二分和三分使用等宽等高分区；减笔画 `㇯` 的内部减号是居中的实心横条，框线仍是虚线。所有图形使用共同细虚线笔触，除方向含义所需外尽量轴对称。

图像对照对新提供的 54×63 上包围截图按原始像素计算。蓝色底框约 39×39，虚线笔画范围约 32×32；映射到 24 单位 viewBox 后，与现有 `2..22` 外框和 `6..18` 内括形一致，所以保留该几何比例并确认角落型复用了同样的 12 单位边长与 4 单位间距。用同一蓝底在内存中栅格化路径，对白色线条掩码做 Dice 与 1px 邻域重合：最终 `2..22` 外框、线宽 0.7 的 Dice 为 0.93、邻域重合 0.97；作为反例，缩小到 `4..20` 且线宽1会降为 0.91、0.93。此比较用 GDI+ 复刻虚线路径而非浏览器逐像素截图；它只比较几何/线宽，不代表浏览器抗锯齿或真人审美验收。

真人 Alt 按住/释放、中文 IME、按键焦点及系统/浏览器冲突仍需实机验收；合成测试不代表 OS/浏览器一定交付相同按键事件。

## 验收边界

- 原有应用自动化和 UI 新增注册表检查由 Node 执行；结果不等同浏览器画面、字体回退、实际尺寸、读屏、触屏或真人 IME 验收。
- 用户指出正在运行的本地静态服务器是正确验收入口；此前把从 `file://` 改到用户给出的 HTTP 页面误称为绕过，是错误判断。本轮通过 `http://127.0.0.1:8765/app/index.html` 复核当前候选：初始侧栏收起；桌面与手机展开/收起状态均可见；手机侧栏改为堆叠，4列 IDC 和偏旁选择区可点；浏览器报告的实际宽度均未出现横向溢出。
- 真实浏览器内的 `Alt+Q` 输入事件插入 `⿸`，随后 `Ctrl+Z` 撤销并恢复测试前源文。候选层只在 Alt 按住期间显示；当前 CUA 按键接口会在截图前释放 Alt，所以没有拿到这一瞬时浮层的截图，仍只对其容器样式做代码/受控检查。真人硬件按键、输入法和系统/浏览器冲突仍待设备验收。空提示 `#notice` 当前为 `hidden=true`、`display:none`、0×0；本地现有的不完整结构会显示轻量“等待下一个部件…”说明。
- 较早候选截图只作为历史记录；本轮截图均来自本地 HTTP 页面。页面静态字体/数据内嵌；本轮未检查浏览器 Network 面板。
- 本地单 HTML、内嵌字体/数据和零外部运行请求架构保留在静态源码；未做浏览器 Network 面板取证。

本机只读私人码表中，`ob+字母` 共 26 组、94 条；只有3组单候选（`m→朩`、`r→亻`、`t→田`），23组存在多候选。`obf` 有5项，数值标记无法支持唯一默认项结论。相关许可头声明私人使用且不得修改/发布，所以这里只记录计数与交互结论，不把完整表复制到产品或仓库。

### 交互候选（未实现）

用户在编辑器聚焦时按 `Alt+Shift+字母`，编辑区旁出现 A–Z 键位图并打开对应 `obX` 组。单字符组直接插入，多候选组展开候选卡：数字直选，Space/Enter 确认高亮项，方向键移动，Escape 取消；没有用户确认默认项时不会按文件顺序猜选。`obf` 的 `扌` 是用户明确指定的默认项，但仍需空格/Enter确认；其余候选及两条多字符提示会分开呈现，多字符提示不会误当成单个 IDS 叶部件。手机继续使用可点的 IDC 与偏旁面板。真实浏览器中已经验证 `Alt+Shift+F` 展开 `obf`、空格插入 `扌`；这是浏览器合成按键验证，不是实体键盘/输入法验收。

### 实机边界

此前从本机 Rime 配置推断 Alt+Shift 会冲突，用户明确指出实际按键不起效、要求忽略该判断；因此这不再阻止候选实现。没有修改输入法配置。当前代码会在编辑器可编辑且 IME 空闲时识别该组合；本轮浏览器确认 UI 分派与候选流程，但实体键盘、真实输入法截获、Alt+方向浏览器保留键仍需单独验收。

### known-gate 明细
